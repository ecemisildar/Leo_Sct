User task: Make a controller for a robot whose task is to push four movable objects into the red area. The robot should move safely through the bounded environment while avoiding obstacles. It should use push as the main progress action to move objects toward the red area. When detect_object_red occurs, all objects are in the red area and the robot should stop or hold position.
Task profile goal: Design a small grid-world DES model for multiple agents. The plant G should model which perception and motion events can occur. The specification E should constrain motion for obstacle-aware movement and make robots push four 1-cell objects into a 2x2 red target area while still allowing all eight controllable actions somewhere in the automaton.
Controllable events: move_forward, move_backward, rotate_clockwise, rotate_counterclockwise, full_rotate, stop, go_to_red, push
Uncontrollable events: path_clear, obstacle_front, obstacle_left, obstacle_right, red_detected, detect_object_red

Reference state semantics:
- clear: no obstacle in front/left/right; safe to advance.
- obs_front: obstacle detected in front region; forward is unsafe.
- obs_left: obstacle close on left; left turn is unsafe; right turn may be preferred.
- obs_right: obstacle close on right; right turn is unsafe; left turn may be preferred.

Reference event semantics:
- move_forward: apply forward motion for 0.2 s (one pulse).
- move_backward: apply backward motion for 0.2 s (one pulse).
- rotate_clockwise: apply clockwise rotation for 0.2 s (one pulse).
- rotate_counterclockwise: apply counterclockwise rotation for 0.2 s (one pulse).
- full_rotate: rotate 360 degrees (atomic action; completes a full scan).
- stop: hold position for one step without translating or rotating; use for deliberate waiting, goal holding, or when no safe movement is available.
- go_to_red: move one grid cell toward the nearest red-area cell; if already in the red area, remain in place.
- push: move toward a movable object; if an object is directly in front, push it one cell forward in the robot's heading and step into its previous cell; if the object cannot move forward, reposition around it instead of repeatedly pushing into a wall.
- path_clear: sensors say forward corridor is clear (no front obstacle).
- obstacle_front: front sensor region is blocked.
- obstacle_left: left sensor region is blocked.
- obstacle_right: right sensor region is blocked.
- red_detected: the agent is inside the 2x2 red gathering area.
- detect_object_red: all four movable 1-cell objects are inside the 2x2 red area.
